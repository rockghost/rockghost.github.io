  • AI 시스템에 의도를 효과적으로 전달하는 방법 이해하기
  • 명확하고 목적 있는 소통의 중요성 인식하기
  • 세 가지 유형의 Description(제품, 프로세스, 성능)에 대한 역량 개발하기

Description 자세히 살펴보기

(4분)

이 영상은 AI Fluency의 Description 역량, 즉 AI 시스템과 효과적으로 소통하는 기술을 탐구합니다. Description은 단순히 프롬프트를 작성하는 것을 넘어, 당신과 AI가 함께 효율적으로 작업할 수 있는 협력적 환경을 만드는 것임을 설명합니다. Description의 세 가지 핵심 구성 요소를 소개합니다:

  • Product Description: AI가 만들어야 할 것을 명확히 정의하기
  • Process Description: AI가 요청에 접근하는 방식 안내하기
  • Performance Description: 협업 중 AI가 어떻게 행동하길 원하는지 정의하기

또한 AI는 당신의 마음을 읽을 수 없으며, 결과의 품질은 자신의 필요, 선호하는 방식, 원하는 상호작용 스타일을 얼마나 명확하게 표현하느냐에 달려 있음을 강조합니다.

핵심 요점

  • Description은 생산적인 협력 환경을 만드는 방식으로 AI와 소통하는 것입니다
  • Product Description은 원하는 결과물, 형식, 대상 독자, 스타일 측면에서 원하는 것을 명확히 정의하는 것입니다
  • Process Description은 AI가 요청에 접근하는 방식을 안내하며, 이는 최종 목표를 명시하는 것만큼 중요할 수 있습니다
  • Performance Description은 AI가 간결해야 하는지 상세해야 하는지, 도전적이어야 하는지 지지적이어야 하는지 등 행동 양식을 정의합니다
  • AI 시스템은 데이터베이스나 자판기가 아닌 상호작용하는 파트너입니다
  • 사전에 명확하게 소통하면 시간을 절약하고 더 나은 결과를 얻을 수 있습니다

연습 문제

나쁜 프롬프트 개선하기

예상 소요 시간: 10분

지침:

  1. Claude에게 개선할 수 있도록 형편없이 작성된 프롬프트를 제시해 달라고 요청하세요.
  2. Description 사고를 적용하여 각 프롬프트를 개선하되, 다음 사항을 고려하세요:
    • 명확한 Product Description (원하는 것이 정확히 무엇인지)
    • Process 안내 (Claude가 어떻게 접근하길 원하는지)
    • Performance 명세 (협업 중 Claude가 어떻게 행동하길 원하는지)
  3. Claude와 개선 전/후 버전에 대해 이야기하고, 개선된 Description이 더 나은 응답을 제공하는 데 어떻게 도움이 되는지 피드백을 요청하세요.
  4. 약 5분 후 역할을 바꿔 Claude가 수정할 나쁜 프롬프트를 제공해 보세요. Claude가 어떤 정보를 추가하고 어떻게 정보를 구성하는지 살펴보세요.

성찰

다음으로 넘어가기 전에 잠시 생각해 보세요:

  • 현재 AI와의 상호작용에서 Description의 어떤 구성 요소(product, process, 또는 performance)를 간과하고 있을 것 같나요?
  • 기대에 충분히 부응하지 못했던 최근의 AI 상호작용을 떠올려 보세요. 더 나은 Description 능력이 있었다면 결과가 어떻게 달라졌을까요?

다음 레슨에서는 4D 역량 중 첫 번째인 Delegation을 자세히 살펴봅니다. 자신의 목표와 AI의 역량을 이해하여 자신과 AI 사이에서 작업을 어떻게 나눌지 전략적으로 결정하는 방법을 배울 것입니다. 이 기초는 창의적 과정과 문제 해결 과정에 AI를 언제, 어떻게 참여시킬지 사려 깊게 판단하는 데 도움이 됩니다.

피드백

강좌를 수강하면서 일상, 업무 또는 수업에서 강좌의 개념을 어떻게 활용하고 있는지, 그리고 어떤 의견이든 들려주세요. 여기에서 피드백을 공유하세요.
